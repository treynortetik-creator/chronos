# Security and correctness audit, 2026-11-10

Scope: Chronos 0.5.0 at `a85c087` (main). Read in full: `bin/`, `lib/`, `ui/*.py`, `hooks/`, `install.sh`, `uninstall.sh`,
`launchd/`, `examples/notify`, the README and `docs/`. `ui/static/app.js` was only scanned for HTML sinks, and
`lib/chronos_api.py` was skimmed (it is a local CLI over functions that were read).

The audit ran on Linux, so nothing here was exercised under real launchd, TCC or a real `claude`. Findings about Claude
Code's own permission matching are marked **suspected**.

Line numbers refer to branch `cloud/audit-security`.

## Open findings

### B-01 (High) The UI token is served to any local client; reads need no token

`ui/server.py:1093` (`_get`), `ui/server.py:973` (`_guard`).

`GET /` returns `index.html` with the token substituted into a `<meta>` tag. The only check on a GET is the `Host` header,
which the client chooses. So any process that can open a socket to `127.0.0.1:4747` can read the token and then use every
mutating route. The same holds for reads: `/api/jobs/<id>` (prompts), `/api/file` (logs and reports, stored 0600) and
`/api/history` need no credential at all.

Reproduced against a throwaway home: unauthenticated `GET /` returned the token, `POST /api/jobs` with it created a job,
`POST /api/jobs/<id>/run` started it, and the run script launched `claude` with the configured `claude_args`
(`--dangerously-skip-permissions` by default).

Who this lets in: another macOS account on the same Mac, a sandboxed app with outbound network access, any service
account. Each gets code execution as the Chronos owner. The README's statement that it takes "anyone who can read
`~/.chronos/ui-token` or run code as you" understates this: loopback is shared by every user on the machine. A browser
on another origin is **not** affected (no CORS, Host check, custom header).

Fix (not small, so not done here):
- Never put the token in a response to an unauthenticated request. Print a one-time login URL at install
  (`http://127.0.0.1:4747/#t=<token>`), have the page store it and send it as the header.
- Require the token on every `/api/` GET, not only the agent-file routes.
- Or bind a Unix socket with mode 0600 and put a tiny proxy in front.

### B-02 (Medium) A long in-session run gets a duplicate headless run

`lib/chronoslib.py:933-959` (`sweep_stale_claim`), `lib/chronoslib.py:1052` (`claim`), `lib/chronoslib.py:979` (`due_jobs`).

A claim taken by `chronos claim <id> --unattended` (the SessionStart hook's timers) has no owner file and no pid, so its
age is the directory's mtime. `due_jobs` does not look at claims, and `claim` sweeps one older than `stale_claim_min`
(45 minutes). Reproduced: session claims at 09:00, tick at 09:50 lists the job as due and its claim returns `CLAIMED`.
Both runs then work on the same day.

It needs an `in_session` job that also has a headless backup (the default for the hook runner, "both"), and a session
run that lasts longer than 45 minutes, or a Mac that sleeps mid-run so the clock jumps. The code already protects headless
runs from this with a pid and start time; session claims have neither.

Fix: have the session refresh the claim (`chronos claim --beat <id>` touching the directory) and sweep on the beat's age,
or record the session's pid at claim time. Until then, raise `stale_claim_min` above the longest session job.

### B-03 (Medium) Secret-path deny list for event and restricted runs has gaps

`lib/chronoslib.py:1300-1326` (`event_deny_rules`).

The README says the list is best effort. Concrete things it does not cover, all readable with the default `Read`:
- `~/.zsh_history`, `~/.bash_history`, `~/.zshrc`, `~/.zprofile`, `~/.bashrc` (exported API keys are common there)
- `~/.claude/settings.json` (`env` often holds keys), `~/.claude/history.jsonl`, `~/.claude/projects/**` (full transcripts)
- `~/Library/Application Support/**` (app tokens, browser profiles), `~/.gitconfig`, `~/.cargo/credentials*`,
  `~/.gem/credentials`, `~/.terraform.d/`, `~/.azure/`, `~/.m2/settings.xml`
- `state_dir`, `logs_dir`, `jobs_dir`, `jobs_file` and `memory_dir` when configured outside `home_dir` and the config
  folder (only those two are denied). Logs and reports of other jobs are then readable by an event run.

With the default tools the only way out is the notify sender and the report, both of which go to the owner
(`bin/chronos-run.sh:229-230` sends the first 700 bytes of the report through `notify`). Any job whose `allowed_tools`
includes a network tool turns this into exfiltration by a stranger's email.

**Suspected**, not verified here: that Claude Code applies a `Read(...)` deny to `Grep` and `Glob` in every case, and
that a `Bash(<notify>:*)` allow refuses command substitution in the argument.

Fix: deny the configured Chronos folders by their real paths, add the files above, and offer an allow-list mode
(`Read(//workspace/**)` only) as the documented default for event jobs. Adding `~/.claude/projects` needs care: a
restricted run with `autoMemoryEnabled` reads its memory there.

### B-04 (Low) Events that arrive while a job is held are lost

`lib/chronos_triggers.py:631` marks the event as seen, then `bin/chronos-tick.sh:84` asks for the claim, which answers
`HELD` (`lib/chronoslib.py:1235`). The log says `TRIGGER claim busy`. Reproduced: the file is recorded in trigger state
and never fires after approval. Fix: skip held jobs in `tick()` before evaluating their triggers, as paused jobs are.

### B-05 (Low) Event run date and event claim date can differ at midnight

`bin/chronos-tick.sh:84-86`. `claim-event` uses its own `now()`, and the run gets a second `chronos today`. Across
midnight the run releases `claim-<id>-<day2>-<hash>`, which never existed; the day-1 claim directory stays for ever.
Fix: have `claim-event` print the date it used and pass that on.

### B-06 (Low, suspected) Sweep and mkdir are separate steps

`lib/chronoslib.py:956-958`, `1097`. Between computing a claim's age and removing it, another claimer can sweep the same
stale claim and take a fresh one, which the first then removes and re-takes. Both return `CLAIMED`. The window is
microseconds and needs a stale claim plus two simultaneous claimers; not reproduced. The run script's `[ -f "$RAN" ]`
check does not cover it (neither run has finished). Fix: take one `flock` on a state-dir lock file around
sweep-check-mkdir in `claim`, `claim_event`, `start_run`, `claim_run` and `start_headless`.

### B-07 (Low) Prompts are visible in the process list

`bin/chronos-run.sh:169` passes the prompt as an argument. On macOS any local user can read another user's argv with
`ps`. The prompt holds the event payload (email text), job memory and `--settings` (including an `apiKeyHelper` command).
`examples/notify/telegram.sh:16-19` likewise puts the bot token in curl's argv. Fix: feed the prompt on stdin
(`claude -p` reads it), and in the example pass the URL through `curl --config -`.

### B-08 (Low) Webhook availability and replay

`ui/server.py:1056-1066`. Ten wrong secrets in a minute lock a hook for everyone, keyed by job id only, so one caller
(through a tunnel: anyone on the internet) can keep a hook locked. `HOOK_FAILS` also grows by one key per distinct id
requested. Authentication is a bearer secret with no timestamp or signature, so a captured request replays for ever.
The handler threads have no socket timeout. Fix: throttle per remote address, cap the dict, accept an HMAC of
`timestamp.body`, set `Handler.timeout`.

### B-09 (Low) Hook arguments are returned without a token

`ui/control_room.py:177` puts the first 40 characters of a hook command's arguments in the row that `/api/control`
serves with no token. The README says the Control Room "never returns hook arguments". A hook registered as
`python3 guard.py --key=...` leaks it. Fix: drop `extra`, or gate `/api/control` behind the token (see B-01).

### B-10 (Low) Agent-file ids and restore

`ui/agent_files.py:151-156`, `450-455`. An id is a slug plus `-2`, `-3` in enumeration order, and history is stored
under the id. Adding a file that sorts earlier shifts the ids, so `restore` can write file A's old version into file B.
Restore also skips the sha conflict guard that save has. Fix: derive the id from a hash of the real path, and require
`base_sha` on restore.

### B-11 (Low) Installer details

- `install.sh:113` renders the plists with `sed` and unescaped paths. A path containing `&`, `|` or `<` produces a wrong
  or broken plist (`plutil -lint` catches only the malformed case). Fix: render with `plutil -replace` or Python's
  `plistlib`.
- `uninstall.sh:23-27` `--purge` removes `~/.local/share/chronos` whether or not the installer created it. A checkout
  that lives there is deleted. It also assumes `home_dir` is `~/.chronos`. Fix: have install write a marker file and
  purge only what carries it.
- `install.sh:105` does not re-apply mode 0600 to an existing token file.

### B-12 (Low) Log retention

`chronos.log`, per-run logs and reports of plain jobs, `notices/` and `history/` grow without limit (`prune` touches
`times` slots only). If the run script itself is killed, `bin/chronos-run.sh:163` leaves `.<log>.raw` and `.err` behind:
the full stream, including tool output. They are mode 0600 and hidden from the UI, but nothing removes them. Fix: prune
by age in the tick, and remove stale dot files.

### B-13 (Low) Polls see ten items

`lib/chronos_triggers.py:361`, `411-413`. Gmail and GitHub polls read the 10 newest items every 10 minutes. An eleventh
new item in one interval is never seen, despite "nothing is dropped". The in-process alarm is fixed at 150 s
(`lib/chronos_triggers.py:650`) while `trigger_deadline_s` is configurable, so the external kill usually wins.
`REPO_RE` (`:58`) accepts `..` as an owner, which makes `gh api` call a different endpoint (owner-set, GET only).

### B-14 (Info) Third-party request from the local UI

`ui/static/index.html:12-14` loads Google Fonts, so each page load tells a third party that the UI is open. Vendor the
fonts and drop the two hosts from the CSP (`ui/server.py:934`).

### B-15 (Info) `CHRONOS_NOW` is not behind `CHRONOS_TEST_MODE`

`lib/chronoslib.py:335`. The other test seams are gated; this one freezes the scheduler's clock if it is ever set in
the launchd environment.

### B-16 (Info) Timing review

No double fire found for missed ticks, sleep and wake, or either DST change: markers are keyed by local date (or
date and slot), a repeated hour fires on its first pass, a skipped time moves to the next valid minute, and yesterday's
open window is evaluated after midnight. Notes:
- Grace and catch-up are wall-clock arithmetic, so on a change night a window is an hour longer or shorter.
- A move to a time zone further east can skip a day's run (its window has passed in the new zone).
- A clock set backwards makes claims look younger, never older, so nothing is swept early.

## Fixed on this branch

Each has a test in `tests/test_audit_2026_11.py` that failed before the fix and passes after.

- **A-06 (High)** `lib/chronoslib.py:120-140`. A `config.json` that exists but cannot be parsed fell back to the
  defaults with one line on stderr. The defaults are the widest settings: `claude_args` is
  `--dangerously-skip-permissions`, `approval_required` is off, `notify` is empty. One stray comma undid every
  restriction and silenced failure alerts. Now `load_config` raises and nothing runs. **Behaviour change**: the UI
  server exits at start with the message in `ui.err`, and the tick logs to `launchd.err`. It is its own commit so it
  can be dropped.
- **A-01 (Medium)** `bin/chronos-tick.sh:80`. `HITS=$(...) || HITS=""` discarded every hit when the pass exited
  non-zero. Hits printed before a deadline kill had already been marked seen (state saved, webhook file deleted), so
  they never ran. The output is now kept.
- **A-02 (Medium)** `lib/chronoslib.py:1835`. `start_run` removed `ran-`, `failed-` and `stalled-` before `mkdir`. A
  Run now refused because a finishing run still held the claim left the day unmarked, and the tick ran it again.
  Markers are now cleared under the claim, as `api claim` already did.
- **A-03 (Medium)** `lib/chronoslib.py:1069`. An unattended claim now answers `NOT_DUE` for a paused job or Pause all.
  A claim by hand is unchanged.
- **A-05 (Medium)** `lib/chronos_write.py:641-651`. `set_config` treated an unreadable config as `{}` and wrote back
  only the new keys. It now refuses and writes nothing.
- **A-12 (Medium)** `launchd/io.github.chronos.ui.plist.tmpl:12-14`. The paths are now arguments
  (`exec "$0" "$1"`), not shell text.
- **A-04 (Low)** `lib/chronos_triggers.py:324-326`. More than 5,000 matching files is now a trigger error, shown in the
  UI, instead of a replay.
- **A-07 (Low)** `bin/chronos-tick.sh:20` sets `umask 077`. Not done: `ui/server.py` still writes history snapshots
  with the inherited umask.
- **A-08 (Low)** `\Z` in `RUN_ID_RE`, `DS_RE`, `MODEL_RE`, `TOOL_RE`, `REPO_RE`, the claim date check and the UI's
  file-name patterns.
- **A-09 (Low)** `ui/control_room.py:309-312` returns the host name only.
- **A-10 (Low)** `ui/agent_files.py:86`, `109`. Exclude globs and the `.env` check ignore case.
- **A-11 (Low)** `ui/server.py:1003`, `1072` refuse a negative length.
- **T-1** `tests/test_times.py` expected `features` without `memory` (red on main since 0.5.0).
- **T-2** `tests/test_api_runs.py` `test_the_stale_sweep_removes_both_files` passed only when the machine's zone was
  New York's; it now sets the zone itself.

## Checked and found sound

- Bind address is `127.0.0.1` only; the Host check stops DNS rebinding; mutating routes need the header token and a
  matching Origin, so CSRF from a web page does not work.
- Path handling: job ids, log, report and history names are pattern-matched and resolved back under their folder;
  symlinks out of `logs/` and `reports/` are refused. The agent-files allowlist resolves real paths and takes no path
  from the client.
- Shell: every value that reaches `eval` is `shlex.quote`d (`shell_env`, `job_env`, `memory-command`); the run script
  validates id, date, hash and type; event text never reaches a shell.
- Event runs never receive `claude_args`; an invalid `allowed_tools` or `restricted` value fails closed.
- Event payloads are stripped, capped and framed with a nonce generated after the payload exists.
- No HTML sink takes server data in `app.js` (two `innerHTML` uses, both constant).

## Test run

`tests/run.sh` on Linux, Python 3: every suite passes except four `Installer` tests in `tests/test_chronos.py`, which
stop at `install.sh`'s macOS check (`Chronos needs macOS (launchd)`). They failed the same way before any change.
The installer and plist were therefore not run end to end; A-12 is tested by executing the template's
`ProgramArguments` directly.
